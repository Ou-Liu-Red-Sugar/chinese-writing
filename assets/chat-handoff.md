# 中文写作交接

只填写本次相关字段；文件放在当前执行者实际可读的任务目录。此包用于协作，不代替其中标明的原始材料。

- 任务ID、当前版本与职责：材料阅读 / 草图作者 / 文字审读与定稿 / 专业审查 / 填充 / 独立读者。一次交接只给本轮职责。
- 当前篇目、已完成前文及本篇完成后的交接对象；多篇请求逐篇执行，不同时下达几篇作者任务。用户监督时写明本轮交回的阶段：
- 本轮允许到达的阶段、返回产物及停止点：首次草图任务到第0版 `sketch_v0`；第1版 `sketch_v1` 形成后送审，后续修订标实际版次；填充须有Lead已核的最终骨架和另行下达的任务。
- 第0版任务：用图、表或思想说明设计[全篇起承转合](../references/composition.md#第0版的起承转合)，将详略、节奏与语气放在同一进程中，并回答六项检查；无需提前写段落或核未填数字。该版作者安排不一并交给后续文字首判者，首判仍先看实际骨架。
- 本次问题、文体、读者已有认识、学习或采用目标：
- 工作区与文件访问方式；允许写入的路径或仅在页面返回：
- 当前用户要求与项目约定的完整入口、必须读取的范围：
- 现行skill版本和相关方法；当前处于取材还是深挖，第1版是否交出并接收，用户设定的停止点：
- 作者任务：第1版本次实际使用的章节/内容/衔接/标点方法；读者依次要理解什么，重点及例子在哪里展开。文字首判不携带这些作者意图，改给实际骨架和声明的读者前提：
- 句子组成职责：本句的主干及承担者，怎样承接前文，所需解释及依据；实际语序、回指、连接与停顿。审读引用具体句群，兼顾语义、语气和节奏，同时检查衔接生硬与提示堆叠，判断增、留、换、删：
- 第0/1版作者：按需给取材所得概述、必要定义或短片段，列资料用途与待深挖之处，不默认附整套数表和核查记录。深挖/专业任务：提供已接收第1版及其需求、原件入口、时点与真实/合成身份。已有原稿和数据暴露如实记录：
- 前文、后文、当前草图/成稿路径和状态：
- 本轮要解决的具体问题与可变部分：
- 已接受事实、表达决定、独立判断前已暴露的内容：
- 预算、足够条件、返回文件名及返回方式：

开始后先说明实际读到的材料范围和影响本轮职责的缺口，再完成本轮职责。缺口写在交接结果中，正文只保留改变理解或采用的条件。调度者须分清当前必须解决的缺口和已安排在后续阶段核实的内容，不能把所有未决项都变成本轮返工。

早期骨架的文字审读任务可直接使用以下说明，并填入稿本和输出位置：

> 本轮是文字首判，只审实际骨架与资料需求，不承担取材、深挖或专业核查。未填数据不影响本轮完成；检查占位在句段中承担的作用，不为核算提前补写。发现可能推翻安排的前提，标出待核关系交回。完成实际起句、承接、句序、标点与需求占位的审读后即可交回。

专业审查任务明确本轮已具备的内容和待核范围，要求返回正确关系、依据及必要条件；文字收尾任务取得这些结果后决定最终措辞、解释层次与显示精度。具体阶段和定稿权限沿[专项检查](../references/specialist-checks.md#2-后续版本的专项检查)。

草图作者返回当前阶段的实际产物：第0版给思想与呈现安排，第1版给真实起句、承接、标点和中间内容的具体语义安排，暂不把中间解释、算例与解析写成正文。Lead先按[阶段接收检查](../references/workflow.md#阶段接收检查)决定接收或退回；全文贴上“草图”标签、把完整答案括作“占位”都不能作为首次骨架。两类审查分别按指定版次、职责与成熟度反馈，作者收到意见后再修订，不自行补写审读者意见。专业意见处理后由文字角色定稿，Lead核结果后才交填充者；填充后的实际正文仍由文字角色最后通读。独立读者只按提供的正文和先修作答，给出答案的正文依据，说明自行调用的额外知识。

返回时附任务ID、输入/输出版本、实际状态、文件或代码块、来源支持范围、未决问题与下一步。不要把“已生成”写成“已验收”，不要把自己的评价登记为用户认可。
