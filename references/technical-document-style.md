# 中文技术文档成稿校对

用于 README、操作说明、教程、接口说明等中文技术文档的定稿或局部编辑。完整写作先完成本 skill 的内容与句群安排；局部编辑只核受影响的文字。然后按当前文档的读者、所属项目约定和呈现载体校对。这里选择性转用[阮一峰《中文技术文档的写作规范》](https://github.com/ruanyf/document-style-guide)；实际阅读范围和取舍见[文献记录](literature.md#技术文档格式)。

## 定位与用词

- 标题准确指向本节内容；检查层级跳跃、同级只有一个小节、上下级标题同名等问题。较短文档可以少设标题；较长手册按读者要完成的任务组织导航，不套固定目录。
- 沿用项目和领域既有术语，组件、状态、动作和保证范围不因求变化而换称。英文缩写在读者可能不熟悉或可能歧义时解释一次。代码实体如标识符、配置键、命令和路径按原样标示，不能为了中文排版改动其字符；具体沿[用户术语偏好](../docs/author-preferences-20260922.md#9-术语稳定)。
- 相邻句中的“它”“该系统”“此时”等回指须能唯一定位。长修饰语妨碍读者辨认对象或动作时，拆开并明确条件、动作及结果；段落围绕一次连续的说明或操作组织。

## 混排、数值与来源

- 中文和拉丁字母相接处通常留一个半角空格；中文与阿拉伯数字之间选定本篇一致的写法，全角标点前不另加空格。代码、URL、公式和文件路径保留自身语法，排版规则不改变内容。中文语句与整句英文分别采用适合其语言的标点；标点的具体用法仍沿[GB/T 15834—2011 的记录](literature.md#标点规范)核对。
- 数值写明对象、单位、期间及比较基准。表示范围时核两端是否共用同一单位，必要时两端都写出单位；“增加了”和“增加到”、“降低了”和“降低到”分别表示变动量和最终值。若倍数或百分比容易误读，直接写起点与终点。
- 引用第三方文字、图表和图片时给出可定位的来源。读者需要复现步骤时，核命令、参数、前提与预期结果的对应关系；这一项是本 skill 的编辑要求，原规范没有提供代码示例规则。

原规范中的固定句长、段落行数、四级标题上限、统一软件手册目录和一律禁用中文文件名，均不作为本 skill 的通用要求。它们只能提示检查具体阅读障碍；正文取舍仍由实际内容、载体和项目约定决定。
