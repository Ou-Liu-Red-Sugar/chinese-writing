# Chat 参与中文写作

Codex 主持本次写作，Chat 承担明确的材料阅读、草图创作或复核任务。此文件规定写作分工与页面交接；浏览器操作使用当时可用工具，不把特定界面版本写死在通用方法中。

## 分工

| 角色 | 接收 | 返回 | 边界 |
|---|---|---|---|
| 取材与深挖执行者 | 取材时接标题、读者与草图问题；深挖时再接已收第1版及具名资料需求 | 取材交主题认识、候选材料与待核问题；深挖交原件、核实结果和采用范围 | 取材够草图使用就停，不提前逐表取数、核算或完成整套研究 |
| 草图作者 | 标题、要求、大纲、前后文、方法与适度取材；后续加入深挖所得资料 | 第0版思想安排、第1版骨架或其后修订 | 早期以概要与需求组织，不因取材不断加深而推迟草图或提前成文 |
| 文字审读与定稿者 | 首判只收读者设定、实际骨架或正文及前后文；后续再收专业意见 | 有位置与原文依据的文字意见；专业意见处理后的最后定稿及精度取舍 | 首判不看作者意图和旧评语，不为未填内容提前核算；最后由本角色组织文字 |
| 专业审查者 | 已写出的具体论述、来源与计算输入、专业方法 | 事实、机制、计算问题，正确内容及必须保留的条件 | 按已有内容审查，不把缺少数值的早期骨架判错；不直接覆盖文字终稿 |
| 正文填充者 | 已验收最终草图、局部空缺任务 | 固定文本不变的完整正文 | 不重新设计结构，不擅改已定标点 |
| 独立读者 | 文章、声明的先修和理解题 | 答案、正文依据、缺失关系 | 不看参考答案、作者解释或预设评价 |

完整专业文章的两类审查分别委派，按实际成熟度出场，不要求每版同时进行。阶段边界、输入分配和最后文字权限沿[专项检查](specialist-checks.md#2-后续版本的专项检查)。一个短小局部任务可以只用一位作者自查；作者自己换身份不构成独立审查。模型、会话、工具和项目记忆可能共享信息，如实登记，不因新开会话就称为隔离盲测。

## 浏览器交接与材料

材料和结果由 Codex 通过 Chat 页面搬运。Codex 读取本地材料后按任务需要直接粘贴、分批发送或上传附件；Chat 在页面返回文本、代码块或可下载文件，再由 Codex 回收保存。沿用用户已经授予的相关材料传输授权，无需逐包重新询问，也不把搬运工作交给用户。

这套流程不使用 C2C，不运行其安装、配对、连接诊断或受保护本地写入。页面或附件出问题时，检查实际发送状态、调整材料分批或格式，并保留已完成工作；不自动恢复已停用的连接器。

把本次所需的 skill、模板和上下文整理成有版本的材料包，注明正式入口、版本和实际传递范围。提供 GitHub 仓库时给出明确版本及 SKILL.md 入口，要求 Chat 实际读取该入口及当前阶段引用的方法；链接已发送不等于文件已读。网页无法读取的具名文件由 Codex 粘贴或上传原文，并记录实际读到的范围。不要假定 Chat 能凭本地路径访问个人 skill 或工作区。

资料工作沿[取材与深挖](workflow.md#取材与深挖)。早期按需交标题、前文及取材所得认识，不默认附整套原件、数表和数值核查记录；已有原稿与数据暴露如实记录。第1版接收后再按具名需求交付深入读取所需资料，未取得原件不记已读。

每次接手重读必需用户要求、方法及当前草图，确认正处于取材还是深挖；早期按需恢复概要和资料需求，不自动重做全部来源核查。项目的全文恢复、会话安排和模型选择按当前任务执行。

## 一次交接

使用 [交接模板](../assets/chat-handoff.md)，保留本次相关部分。明确一项职责、输入版本、实际输出文件、允许改动、完成条件、预算和当前状态，尤其标明本轮允许到达的阶段。题目与参考答案分开给；独立首判者不接收Lead的预定结论。

以草图协作为例：

1. Codex给标题、读者、范围、前后文与方法，取材到足以组织本篇后，作者交第0版思想与资料需求。回收后核安排，不在同次返回里一并生成第1版、审读和正文。
2. 另行形成第1版，作者先实际使用 [章节、内容、衔接及标点方法](specialist-checks.md#1-第1版生成时使用的方法)，再确定各段内容及前后句的承接对象、所需解释、真实衔接句与标点，暂不展开中间句子。回收后另给文字审读者可连读的骨架，首判不附作者意图与旧评语；明确本轮只核文字组织，未填数字不影响这一阶段完成。
3. Codex按[阶段接收检查](workflow.md#阶段接收检查)核实际第1版及取材深度，提前成文或越界深挖均记真实问题，不能追认合规。第1版接收且任务允许继续后，按资料需求派发深入读取与核实；所得内容及文字反馈共同进入修订，专业角色核已采用内容。不为填满材料清单搜无关资料，也不借承重前提提前完成深查。
4. Codex解决内容分歧后，交文字角色最后编辑并决定表达精度，核结果及两类意见处置，再按 workflow 第4节另发局部填充任务。
5. 填充者只补局部文字。固定部分、事实与阅读任务的必要核对完成后，由文字角色最后通读正文；后续专业问题仍交文字角色落笔，完成后交付正文及可查过程入口。

任务明确由Chat完成时，不因等待而悄悄替换成Codex自写。等待与修订计入预算；无新结果不重复发送。超时先确认原会话状态，避免两份任务同时运行。页面故障先核实际状态并作有依据的恢复；只有确需用户登录或补充决定时交回用户。

## 回收与续接

Chat 在页面提供完整文件或代码块，Codex 复制、下载或提取可见正文后保存，核对任务ID、版本、完整性和实际内容。页面生成、已回收、已验收分别记录；本地写入由 Codex 完成，不要求 Chat 调用本地工具。

记录实际会话URL、界面可见模式/档位、消息数、已暴露输入、回收方式、当前版本、剩余问题与下一步。看不到的模型字段写未知，不用模型自报替代界面观察。

跨会话交接只带当前任务所需材料、已采用决定、当前最终/中间草图、未决问题和下一步。Chat 分发副本与正式 skill 版本不一致时先更新分发包；不能在旧会话口头追加几条后把它当现行方法。
