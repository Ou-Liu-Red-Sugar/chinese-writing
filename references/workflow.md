# 中文写作 workflow

这是独立写作流程，可用于教材、技术说明、研究报告和参考记录。知识库、研究项目及其他调用场景分别接入自己的材料、内容职责和发布方式。Codex 负责范围、事实采用、最终草图验收与交付；Chat 或子 Agent 按具名问题参与。正文的语句组织沿 [composition](composition.md)，限定处理沿 [qualification](qualification.md)，评测沿 [benchmarks](benchmarks.md)。

## 1. 任务与材料

确定对象、读者、用途、前文与后文、篇幅或时间限制、信息时点、允许修改的文件。读者数学程度与专业知识分别判断。教材为初次接触的读者补专业前提；研究报告继承已经完成的研究，不因精简重新研究，也不把摘要冒充完整研究。

任务分成以下实际职责，按需要选用：

| 模式 | 完成标准 | 常用组织 |
|---|---|---|
| 教材讲解 | 读者能解释、计算或迁移一项明确关系 | 定义、例子和推导按理解次序展开 |
| 说明文章 | 读者能理解对象、过程、区别或操作 | 围绕对象的实际关系连续说明 |
| 研究报告 | 读者能复原判断的依据，识别影响判断的条件 | 当前结果、依据与必要计算、条件与证据入口 |
| 参考记录 | 读者能准确查询并核回来源 | 稳定命名、单位、期间、字段及说明 |

混合文章明确主用途；原表、证明、来源记录可置于分支或附录，仍保留任务要求的完整内容。教学带读若需要先见全表结构，就先给其结构与各板块关系，不能只为压缩隐藏必要材料。

开始实质写作前，读取足以支持本题的原件和对应知识材料。已有有效输入可复用；新事实按任务核实。项目要求先检索教材、实例和近期研究时执行该要求。封闭材料的写作练习按题设工作，不凭空补成真实公司事实。

说明本轮预计时间或调用数及完成条件；预留整合、事实核对和交付。未指定预算时给合理估计。一般不向用户追问能从上下文取得的文风；缺失信息会改变对象、读者或采用结论时才问。

## 2. 第0版与第1版草图

### 第0版：思想及其呈现方式

先判断本篇要建立哪些认识，各项之间有什么关系，再选择相应材料与表现办法。可以用流程图、表格或简要文字，列出思想、前提、先后或并列关系，以及用什么解释、对照、例子、推导或图表把它体现出来。详略在此先作安排，不要求写出段落、衔接句和完整正文，也不强制一种图表格式。

第0版需要超出知识点清单：每项思想都能说明怎样让读者理解，以及它与中心和其他思想的联系。保存为 `sketch_v0`，Lead核其内容与呈现安排后进入第1版；无需为第0版机械增加独立审稿人。首次草图任务明确到本版止，不能在一次返回里补写全部阶段。

### 第1版：段落、衔接和标点骨架

第1版生成前就实际调用章节安排、材料取舍与详略、段落衔接、句法和标点的具体方法，入口及所需产物见 [写作方法调用与专项检查](specialist-checks.md#1-第1版生成时使用的方法)。这些方法决定第一版怎样组织文章，不能等骨架写完后只作总体评价。重要安排简记采用依据，不要求逐句附文献。

把第0版落实到实际段落次序。说明每段大致写什么、需要展开哪些内容、承接前文哪一点以及把什么留给后文；写出真实的起句或衔接句，安排实际标点，并用明确占位说明标点之间的内容。第0版的一项思想可以分成几段，几项相关思想也可以合为一段，不作一一机械映射。

标点同时帮助安排尚未写出的中间句子。例如冒号后要解释什么，分号两侧比较哪些同层内容，在哪个句号处完成一个意思、下一句再接什么。中间句子此时暂不展开；审读不能因没有填满正文而判第1版失败。表格只能补充段落职责，不能代替本版需要呈现的衔接句与标点骨架。具体形式见 [草图模板](../assets/article-sketch.md)。

句子的起承转合也在本版体现，使用 [句子组成方法](sentence-construction.md#1-先安排句群承担的动作)。先确定前一句留下的对象、判断或动作，后一句接着它增加什么，以及其间是否缺少读者需要的解释。把共同完成设定、解释或推论的分句组织起来，写出承接对象、实际引入及回指、必要关联词、句界和公式入口。中间专业内容可以占位，但所需理由的具体含义及其进入位置要已确定；“〔补因果〕”“本段承上启下”不能代替组句。关系表达、中间内容与材料依据的不同缺口按该方法处理，不能只添连接词，也不能为连贯编造事实。具有推广、设定或操作作用的作者引导按当前用途保留。

保存第1版后再取得针对它的反馈，状态为 `draft_for_review`，记录 `sketch_version: v1`。后续v2、v3等按实际问题修正这份骨架，包括思想落点、段落次序、详略、衔接句和标点；不把后续修改机械理解成每轮填进更多中间句子。直到骨架彻底建好、剩余内容可以按已定位置局部填入，才验收为最终草图。

各版保存实际形成时的内容，不能从全文倒拆第0版和第1版充当既往过程。既有版本系统或同一任务记录即可，无需为每次改字新建文件；需要能取回第0版、第1版、反馈与实际修订。

## 3. 草图修改与最终验收

**先取得真实反馈，再作处置。** 新写或实质重写文章通常由另一位实际执行者审读已保存的草图；可用 Chat 或子 Agent，不机械增加阵容。执行者不可用时，Lead 在另一个明确的审读阶段重新取得该稿并作有据自查，标明自查身份。不能让作者代写另一位审读者的意见，也不能在同一次文章生成中同时补齐全部反馈和验收字段。

第1版之后须完成适用的专项检查：篇章/章节与内容安排、段落衔接、句法与标点、必要限定与防御性措辞。各项的具体输入、问题和返回要求统一见 [专项检查](specialist-checks.md#2-后续版本的专项检查)。一次执行可以承担多项，但要分别提供实际结果；笼统通读、算术核对和总分不能替代。后续按真实改动复核受影响专项，无须固定阵容或反复全量检查。

审读先确认当前版本。第0版核思想、材料及呈现方式；第1版及后续版本先沿骨架正文、明确占位及实际前后文连读，再参看作者对段落职责的说明。检查同时覆盖段间与句间连接，反馈定位具体前后句、公式或转换，说明已有信息怎样支持下一步，或缺了哪项内容与依据。主题相同、各节顺序合理不能代替语句衔接；“通顺、完整、通过”不构成反馈。保持原文也须指出实际承接及理由，不用作者本来想表达的意思替稿件补解释。引用文献时落到当前问题。

下面是需要解决的问题种类，可以一次同时解决多项，也可以针对同一问题继续修改；不规定四轮或五轮，不为了填满检查表重写已成立的文字。

1. **内容与依据。** 判断成立，定义和条件完整，材料支持本句，推导和数字能核回；未知只影响对应命题。
2. **材料与详略。** 中心关系具体展开；次要经过保留理解所需的联系；背景不挤占难点；必要材料未因精简退出。
3. **篇章与句序。** 标题与内容相符；同一解释连续完成；话题移动清楚；前后文决定局部同样成立的句子怎样排列。
4. **句法与标点。** 第1版先核已经写出的骨架句，并通过标点安排中间内容的层级、范围和顺序；后续使主体、动作、修饰范围与填充位置逐渐明确。中间句子未展开时不虚报逐句通顺检查，用文献的具体辨析处理实际写出或安排的部分。
5. **文体与限定。** 教材展开必要步骤；报告让判断直接可用；删除不承担语义作用的防御性表态；结构说明只在确实帮助阅读时进入正文。
6. **连续试读。** 按 [专项检查](specialist-checks.md#2-后续版本的专项检查) 连读全稿，尤其核转折、办法更换、新对象引入及动作推进等有实质作用的连接。前后句的承接对象、关系和必要解释应能在当前骨架中定位；读者需自行补出的承重内容记回草图。只对实际问题及重要保持判断留记录，不机械为每句制表。最终骨架和填充后的正文分别按实际完成程度核读。

将反馈逐项采用、调整或不采用，保留理由及处理后的实际位置。确需改动就保存修订稿；确无必要改动时引用原稿并给出具体保持依据，不复制文件或改几个同义词凑版本。语义、篇章或表述仍有承重问题，就继续这一阶段。

满足以下条件，Lead 才把草图记为 `final_sketch`：

- 能取回第0版思想及呈现安排、第1版段落和标点骨架，以及针对相应版本的原始反馈、实际修订。
- 审读意见已有实际处置，处理后的稿件与处置记录对应。Lead核看关键前后文和实际改动，不只看作者的“已处理”摘要。
- 第1版已据具体写作方法形成安排，后续适用专项有实际反馈与处置；采用、修改或保持的理由能定位到骨架。

- 篇章、段落边界、句序和承接已经写定；主要标点已落在骨架中，其前后内容及辖域明确。会影响理解的句间关系已有实际文字和依据，不能仅凭连词存在或职责说明验收；承重解释仍需在审读意见中另行补讲的，退回草图。
- 必要的定义、机制、结论、计算、条件、时间、单位和引用位置已经确定。
- 剩余中间文字只承担已确定的局部表达，内容、前后关系及语法位置清楚；不能把整个论证、段落衔接或句法设计留成占位。
- 预计填入的局部几十字可以嵌入固定句子，不要求填充者再决定段落、句序或标点。
- 所有会改变文章采用的意见已经解决，或按确切范围保留真实未决事实。

“几十字”表示局部填充的尺度，不能据此设每篇固定空缺数、总长度比例或总字数。复杂解释需要写多长，就在草图阶段写到足以确定这些关系。正文已经齐备时可无空缺。

冻结时保存任务/材料版本、送审稿与反馈入口、处理后草图版本、实际审读者和Lead验收理由、未填位置及允许内容。状态推进的依据是这些实际材料，不能只改一个状态字段。保存的是可检查的作品与取舍，不要求展示隐藏思考过程。

## 4. 填充正文

**生成前核对。** 协调者先取得送审稿、原始反馈、处理后草图和该版验收记录，核对它们的版本关系与承重意见处置。缺材料、反馈只含笼统通过、反馈对应旧稿、处置无法在文字中找到，均不进入正文阶段。将欠缺项目记回草图任务；不能先生成正文再补齐记录。已知直接跳过审读的，判执行不合格，不降格成“记录不详”。

核对完成后，另行给出正文任务，只交当前已验收草图和局部填充范围。填充者保持固定文字、标题、段落、句序、承接和标点；局部文字不得补出新结论或改变条件。全文已齐备时可以直接采用，但此前的实际审读及处置仍要存在。

可用 `{{FILL:S1}}` 这类唯一标记标识空缺。每项填充给语义任务、实际输入和局部长度上限；外层标点写在草图中。全部填充后与最终草图逐处对照。纯手工成稿也履行同样的对应检查，无须为了工具改正文格式。

发现实质错误，或填入后仍须改句序、补承重解释才能接上时，保留当前草图并撤销其验收状态，列具体前后文问题，回到第3节修订并重新验收后生成正文。不得静默改变固定部分，也不把这一恢复途径当作正文可以随意重构的许可。

## 5. 核对与校准

分别检查：草图与审读过程是否实际发生；事实与计算是否成立；成稿是否忠实填充；表达是否清楚；读者能否完成任务。按 [benchmarks](benchmarks.md) 记录对应证据，不能用其中一项代替其他项。固定文字比对只证明后半段的填充对应，不能追认缺失的草图审读。

精简研究报告逐命题复核删前删后：确定性、条件范围、数字分母、时点、来源归属、未识别部分和行动含义是否相同。必要条件在每个可以独立使用的交付单元中说清一次；正文内反复的泛化提示删除。实际取舍留既有研究记录。

需要检验教学效果时，让另一位执行者只接收文章、先修和具体理解题，给出答案及正文依据；不把作者的解释或参考答案同时给他。模型读者的表现单独标识，用户是否认可另记。

出现具体问题，修订对应最早阶段及受影响下游。一次合并反馈后仍有承重分歧，先定位原因和代价，不能不停增加审稿人或改写轮次。达到任务完成条件即交付。

## 6. Chat 协作与批次

任务可由 Codex 完成；篇幅大、材料分支可分、草图有争议或需要独立读者时，选择 [Chat 协作](chat-collaboration.md)。Chat 可以读材料、编写和修改草图、挑战承接关系、按最终草图填充或承担阅读检验。分派具体产物和边界，避免多人重复生成整篇文章。

批量写作先用有代表性的少量篇目检验流程，再在已授权批次内展开；不固定篇数或作者阵容。每篇保留自己的问题、材料、最终草图和结果。跨篇共享术语与来源，不共享成套开头、段长和结尾。

用户无需逐篇确认普通草图。Lead 在已授权范围内处理取舍；用户提出的风格修正登记为明确要求；从单例总结的写法保持为待检验推论，换题观察。

## 7. 保存、交付和恢复

正文和必要附件进入本次任务的正式目录；原材料与判断沿原有来源ID复用。若项目已有生产记录，写入其相应字段，不新建平行台账。没有记录结构时，可在同一 `writing-record.json` 中保存：

- 任务、文体、读者、版本、预算、材料与前后文入口；
- 已读文件及范围、实际执行者、Chat URL/消息计数/模式观察；
- 审读前草图、原始反馈、逐项处置与处理后草图、最终验收、填充与成稿入口；
- 内容/表达/流程/阅读测试的真实结果、用户反馈身份；
- 完成、待修改或暂停状态，以及具体下一步。

状态按实际推进：`materials`、`sketch_v0`、`sketch_v1`、`draft_for_review`、`review_received`、`feedback_resolved`、`final_sketch`、`filled`、`reviewed`、`delivered`。状态与草图版本分开记录：v2、v3等表示骨架的实际修订，不是固定轮次；不得凭状态数声称工作充分。恢复先取得当前版本对应的思想安排或段落骨架、原始反馈、实际处置和待办，再读取当前及之后的方法部分；不重开已完成研究，不恢复未获指示解除的暂停任务。

写作交付不自动公开发布、改变研究模型或发送给他人。页面、原表、引用和教学附件的同源生成沿调用项目规定。
